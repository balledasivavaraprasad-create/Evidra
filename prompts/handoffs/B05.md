## Implemented behavior

1. **Leakage-Safe ML Ranking Pipeline (`backend/app/screening/ml/pipeline.py`):**
   - Implemented `train_ranking_model`: fits `TfidfVectorizer` (sublinear TF, ngrams 1-2, English stop-words) and `LogisticRegression(class_weight="balanced")` strictly on training data.
   - Guaranteed zero feature/vocabulary leakage: held-out records never participate in vectorizer fitting.
   - Handles edge cases gracefully without throwing uncaught exceptions:
     - Fewer than 4 samples -> `MLRankingStatus.UNAVAILABLE_INSUFFICIENT_DATA`.
     - Single-class training data -> `MLRankingStatus.UNAVAILABLE_SINGLE_CLASS`.
     - Empty text/vocabulary -> `MLRankingStatus.UNAVAILABLE_EMPTY_VOCAB`.
   - Pure scoring function `score_and_rank_records`: calculates priority scores in `[0.0, 1.0]`, ranks descending, and produces `RankedRecord` list without altering input records or mutating database state.

2. **Cryptographic Checksum Verification & Security (`backend/app/screening/ml/pipeline.py`):**
   - Implemented `save_model_artifact`: saves `model.joblib` and generates `manifest.json` with cryptographic SHA-256 checksum and metadata (sklearn version, train record count, vocabulary size, feature config).
   - Implemented `load_model_artifact`: validates SHA-256 file checksum before unpickling/loading. Rejects tampered files or checksum mismatches (`MLRankingStatus.UNAVAILABLE_CORRUPT_ARTIFACT`), preventing arbitrary deserialization exploits.

3. **High-Level Ranker Service & Evaluation Metrics (`backend/app/screening/ml/ranker.py`):**
   - `MLScreeningRanker`: encapsulates loading, validation, and execution. If disabled or artifact missing, gracefully returns typed unavailable status (`MLRankingStatus.UNAVAILABLE_DISABLED`), letting deterministic rules continue uninterrupted.
   - Implemented `compute_recall_at_k(ranked_records, ground_truth, k)`.
   - Implemented `compute_work_saved_at_recall(ranked_records, ground_truth, target_recall=0.95)` computing Work Saved at 95% Recall (WSS@95).

4. **Comprehensive Unit Test Suite (`backend/tests/algorithms/ml/test_ml_ranking.py`):**
   - 8 unit tests validating:
     - Insufficient samples (< 4) returns `UNAVAILABLE_INSUFFICIENT_DATA`.
     - Single-class training data returns `UNAVAILABLE_SINGLE_CLASS`.
     - Empty vocabulary returns `UNAVAILABLE_EMPTY_VOCAB`.
     - Zero leakage: held-out record tokens (`supercalifragilistic`) do not appear in vectorizer vocabulary.
     - SHA-256 verification and tamper rejection: corrupted joblib bytes are detected and rejected.
     - Determinism: identical inputs produce identical scores and ranks.
     - Graceful fallback when disabled via configuration.
     - Metric accuracy for Recall@k and WSS@95.

5. **Benchmark Evaluation & Report (`evals/ml/`):**
   - Clustered split by `group_id` across 40 clinical records (26 train, 14 holdout) ensuring zero paper/study duplicate leakage.
   - Evaluated against fixed default ordering and explainable rules baseline:
     - Classical ML Ranker achieved **30.7% WSS@95** and **100% Recall at 75% screened**.
     - Average inference latency: **0.077 ms/record** (1.07 ms total).
     - 0 external network/model calls (100% offline).
   - Documented in `evals/ml/results.md` and `evals/ml/benchmark_report.json`.
