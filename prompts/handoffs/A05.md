## Implemented behavior

1. **API Client Additions (`frontend/src/api/client.ts`):**
   - Added typed interfaces: `CorpusDiffResponse`, `SnapshotRestoreRequest`, `RestoreMode`.
   - Exposed API endpoints:
     - `api.revisions.getDiff(workspaceId, baseRevisionId, targetRevisionId)` -> `GET /api/v1/workspaces/{id}/diff?base_revision_id=...&target_revision_id=...`
     - `api.revisions.restore(workspaceId, snapshotId)` -> `POST /api/v1/workspaces/{id}/restore?snapshot_id=...`

2. **Conflict Resolution Modal (`frontend/src/features/conflicts/ConflictResolutionModal.tsx`):**
   - Implemented dialog displaying competing reviewer events, reviewer identities, timestamps, and conflicting statuses (`INCLUDE` vs `EXCLUDE`).
   - Requires deliberate human selection of resolved status (`INCLUDE`, `EXCLUDE`, `MAYBE`).
   - Enforces non-empty resolution rationale (`rationale` string with validation).
   - Passes expected `version` for optimistic locking (`409 Conflict` detection if resolved concurrently).
   - Emits `POST /api/v1/workspaces/{id}/reviews/decisions` with `event_type: "CONFLICT_RESOLUTION"`.

3. **Version History & Diff Page (`frontend/src/features/history/HistoryPage.tsx`):**
   - **Timeline View:** Lists query versions, corpus revisions, and saved snapshots with creation timestamps, criteria hashes, and execution metrics.
   - **Corpus Diff Visualizer:** Compares base and target revisions side-by-side:
     - Added vs removed records.
     - Merged groups vs split groups.
     - Representative shifts and candidate edge changes.
     - Displays stage invalidation fingerprint badges from C04.
   - **Conflicts Tab:** Surfaces active unresolved group conflicts with direct button to trigger `ConflictResolutionModal`.
   - **Exact Restore Flow:**
     - Restores exact historical corpus snapshot (`RestoreMode.EXACT_SNAPSHOT`).
     - Clearly labels historical cutoff time and decision boundary.
     - Performs 0 external network requests and 0 algorithm recomputations.

4. **Unit & E2E Verification Suites:**
   - Unit tests (`frontend/src/tests/history_restore.test.ts`):
     - Validates diff payload parsing and record/group partition accounting.
     - Validates conflict resolution payload construction and rationale enforcement.
     - Validates exact restore dispatch with query parameters.
   - Acceptance test (`frontend/tests/e2e/level2/restore.spec.ts`):
     - Playwright scenario verifying conflict resolution, diff inspection, and snapshot restoration.
