## Implemented behavior

1. **Snapshot Restoration & Invariant Preservation (`snapshots.py`):**
   - Implemented `restore_corpus_snapshot(db, workspace_id, snapshot_id, mode, expected_workspace_version)` without any live network or external API re-fetching.
   - Restores exact historical record revisions, paper groups, representatives, and criteria saved in `corpus_members` and `group_snapshots`.
   - Protects historical data: snapshots remain strictly immutable; new reviewer decisions are appended as review events.
   - Enforces optimistic concurrency via `expected_workspace_version` check against `WorkspaceModel.row_version`.

2. **Group Lineage & Decision Projection (`snapshots.py`, `corpus.py`):**
   - Automatically detects group transitions across corpus revisions: `merge`, `split`, `extend`, and `retain`.
   - Records provenance in `GroupLineageModel` with child and parent group references.
   - **Decision Carryover:** Propagates human screening decisions from parent groups to child groups with full provenance (`actor_id`, `reason`, `supersedes_event_id`, and `inherited=True` in payload).
   - **Conflict Detection:** When an Included group and Excluded group are merged, automatically creates an unresolved `ReviewConflictModel` (`kind="decision_divergence"`), placing the merged group in `EffectiveDecisionState.CONFLICT`.
   - **Export Protection:** `export_corpus_studies` verifies effective state and conflict status; groups with unresolved conflicts are excluded from exports.
   - **Split Ambiguity:** Group splits record `GroupLineageOp.SPLIT` and flag prior merged decisions with `ReviewConflictModel` (`kind="split_ambiguity"`) for reviewer reaffirmation.

3. **Structured Corpus Diff & Deterministic Fingerprints (`snapshots.py`, `models.py`):**
   - Implemented `compute_corpus_diff(db, base_revision_id, target_revision_id) -> CorpusDiffResponse`.
   - Calculates exact added, removed, and retained records and record IDs.
   - Reports group-level additions, removals, merges, splits, and representative changes separately from record counts.
   - Generates a deterministic SHA-256 `invalidation_fingerprint` over structural changes and criteria version for downstream consumption by C04.

4. **REST API Routes (`main.py`):**
   - `GET /api/v1/revisions/{revision_id}/diff?base_revision_id=...` -> returns `CorpusDiffResponse`.
   - `POST /api/v1/workspaces/{workspace_id}/restore?snapshot_id=...` -> returns `CorpusRevisionResponse`.
   - Exported OpenAPI schema (`contracts/openapi.json`) and regenerated frontend TypeScript declarations (`schema.d.ts`) with zero drift.

5. **Atomic Publication & Failure Isolation:**
   - In `process_corpus`, `WorkspaceModel.current_revision_id` is updated only after all deduplication, screening, PICO, and lineage operations succeed.
   - Failures trigger an atomic `db.rollback()`, leaving previous active revision completely intact.
